# 四类媒介示例项目页面计划

> 状态：提案。本文档规划“示例项目页面”，不等同于现有项目类型模板，也不代表页面功能已经实现。

## 目标

为第一次使用 GenStory.cc 的用户提供一组可直接理解的创作案例。用户看到的不是一份空白项目结构，而是一条从故事想法、第一次提示词到最终作品的完整过程：

```text
故事概念
    ↓
正典与角色设定
    ↓
媒介规划
    ↓
分步创作
    ↓
人工检查与修改
    ↓
最终作品
```

示例项目统一采用同一核心故事：一名日本高中男生从某天开始能看见教学楼窗外的一道裂缝，其他人却完全看不到。相信他的青梅竹马陪他在放学后调查裂缝；当各种设备都无法发现异常时，男生决定亲手接触裂缝，裂缝产生吸力，女生试图抓住他，最终两人一起被吸入异世界。第一章表现“异常的发现与建立约定”，第二章表现“调查失败与穿越发生”。后续小说、漫画、视觉小说和互动视频都从这一版共享正典继续展开。

页面需要让用户回答三个问题：

1. 这个项目最后做出了什么？
2. 它是怎样一步步做出来的？
3. 我能不能从某个步骤开始，改成自己的项目？

## 示例项目与类型模板的区别

| 对比项 | 类型模板 | 示例项目 |
| --- | --- | --- |
| 目的 | 提供某种项目类型的可复用起始结构 | 展示一个项目从开始到完成的真实创作路径 |
| 内容 | 最小必要文件、规则和示例结构 | 故事正典、过程节点、Prompt、模型信息、修改记录和最终产物 |
| 起点 | 用户创建新项目时复制 | 用户浏览案例，也可以从任意节点派生新项目 |
| 进度 | 没有创作进度语义 | 每个节点有状态、依赖、产物和完成条件 |
| 模型记录 | 不属于模板正文 | 是示例项目的核心展示内容 |
| 变更方式 | 用户直接编辑模板生成的项目 | 记录每轮 AI 生成、人工选择、修改和验证 |
| 复用方式 | 复制整个类型起始结构 | 复制完整案例、单个节点，或只取正典/角色/Prompt |
| 交付标准 | 能创建并打开一个合法项目 | 能解释从概念到最终作品的完整过程，并展示可运行或可预览的结果 |

类型模板继续保存在 `public/templates/<lang>/`，只负责新项目初始化。示例项目应使用独立的案例数据和页面入口，不修改模板文件来承载过程记录。

```md
## Core Premise

在现代日本，一名高中男生某天开始能够看见教学楼窗外的一道裂缝。其他人看不到裂缝，也无法理解他的描述。男生的青梅竹马相信他，和他约好放学后一起调查。调查时，拍照、电磁检测等各种设备都显示一切正常。男生决定从窗子探出手去接触裂缝，裂缝突然产生吸力；女生想抓住他，结果两人一起被吸入裂缝，穿越到异世界。

## Story Promise

- 以两个日本高中生的日常关系作为异世界冒险的情感起点。
- 第一章完成“发现裂缝、无人相信、青梅竹马相信并约定调查”。
- 第二章完成“放学后调查、设备检测无异常、接触裂缝、两人一起被吸入”。
- 异世界的具体规则、回归目标和长期冲突在穿越后的共享设定阶段继续建立。

## Confirmed Timeline

1. 男生开始看见教学楼窗外的裂缝。
2. 其他人看不到裂缝。
3. 青梅竹马相信男生。
4. 两人约好放学后调查。
5. 放学后使用拍照、电磁等设备调查。
6. 各种设备都无法发现异常。
7. 男生从窗子探出手接触裂缝。
8. 裂缝产生吸力。
9. 女生试图抓住男生。
10. 两人一起被吸入裂缝，穿越事件发生。

## Chapter Boundaries

### Chapter 001: The Crack Outside the Window

男生第一次确认自己能看见裂缝，尝试向同学或周围人求证但无人看见。青梅竹马没有直接否定他，而是选择相信他，并约定放学后一起调查。章节结尾应保留裂缝的神秘感和调查约定。

### Chapter 002: After-School Investigation

两人按照约定在放学后调查裂缝。拍照、电磁检测等各种设备都和其他人一样看不出异常。男生决定从窗子探出手去接触裂缝；裂缝开始产生吸力，女生想要抓住男生，结果两人一起被吸入裂缝。章节结尾为穿越后的未知环境，不提前确定异世界的完整规则。

## Canon Constraints

- 两人必须是日本高中生，并且是青梅竹马关系。
- 裂缝在第一章和第二章中只有男生能直接看见；设备无法确认异常。
- 女生的相信和主动调查是两人共同穿越的前置原因。
- 第二章的穿越由男生主动接触裂缝触发，女生因试图抓住他而一起被吸入。
- 第一章不提前解释裂缝的来源。
- 第二章不提前写完异世界设定；穿越后的世界观属于后续共享设定阶段。
- 漫画、小说、视觉小说和互动视频可以改变分镜、叙事视角、镜头、对白长度和交互方式，但不能改变上述事件顺序和因果。
```

## 第一个用户 Prompt

以下 Prompt 是本示例项目的第一个用户 Prompt，必须原样保留其原始含义。允许修正分段、标点和执行结构，但不能提前补充异世界设定、改变章节事件，或把“女生想要抓住男生后一起被吸入”改成其他穿越原因。

## 产品范围

### 首批四个媒介案例

四个案例共享同一个项目宇宙和核心人物，但拥有各自的媒介目标、文件产物和验证方式：

| 媒介 | 示例目标 | 关键过程 | 最终展示 |
| --- | --- | --- | --- |
| 小说 | 完成一部短篇或第一章 | 大纲、章节、场景、人物弧线、文本修订 | 可阅读正文和章节目录 |
| 漫画 | 完成一章短篇漫画 | 分页、分镜、对白、构图、画面一致性 | 页面缩略图、分镜与最终页 |
| 视觉小说 | 完成可运行的第一章 | 剧本、场景状态、角色立绘、分支和预览检查 | 浏览器内视觉小说预览 |
| 互动视频 | 完成带选择点的短片段 | 片段、时间轴、旁白、选择、视频和音频资产计划 | 片段播放器或交互流程预览 |

“完成”在四种媒介中不要求生成同一种文件，而是要求该媒介的最小可验证成品存在。暂未生成的图片、音频或视频必须在页面上标注为“待生成资产”，不能伪装成最终成品。

### 共享正典

共享正典只有一个来源，四种媒介只能引用或扩展它，不能各自重新定义事实：

```text
example-world/
├── meta.md             # 项目主题、语气和核心冲突
├── references/
│   ├── glossary.md     # 世界术语与专有名词
│   ├── timeline.md     # 穿越前后事件顺序
│   ├── rules.md        # 异世界规则与限制
│   └── canon.md        # 已确认事实和不可改写事件
├── characters/
│   ├── male-student.md # 男高中生的身份、动机、状态变化
│   └── female-student.md
└── locations/
    └── otherworld-gate.md
```

角色名称、年龄、穿越事件、首次抵达地点和第一章结局应在首个节点确认后冻结。后续节点如需改变，必须记录为“正典变更”，说明原因、影响范围和受影响的媒介产物。

## 创作过程模型

### 阶段定义

示例项目的最小展示单位不是单条 Prompt，而是“阶段”。每个阶段有明确初始状态、阶段目标、多个过程节点和达成条件。用户应能看到：阶段开始时还缺什么，连续使用哪些 Prompt 和模型，经过哪些人工判断，最后为什么可以判定这个阶段完成。

```ts
interface ExamplePhase {
  id: string;
  exampleId: string;
  trackId: "shared" | "book" | "comic" | "visual-novel" | "interactive-video";
  sequence: number;
  title: string;
  initialState: string;
  goal: string;
  acceptanceCriteria: string[];
  status: "planned" | "in-progress" | "completed" | "needs-review";
  dependsOn: string[];
  stepIds: string[];
  outputs: OutputRef[];
  completedBy?: string;
}
```

阶段规则：

- `initialState` 描述阶段开始时已有材料和缺口，例如“只有故事种子，没有角色姓名和异世界规则”。
- `goal` 描述阶段完成后必须达到的创作状态，例如“冻结两名主角档案，并能被四种媒介复用”。
- `acceptanceCriteria` 是阶段能否完成的判断标准，不能只写“生成完成”。
- `stepIds` 按顺序连接多个 Prompt 节点，展示从初始状态到阶段目标的真实推进。
- 一个阶段可以包含探索、生成、比较、修订、校验和冻结等不同类型的 Prompt。
- 阶段完成必须由最后一个或多个校验节点证明，而不是只因为模型输出了一段内容。
- 分支阶段依赖共享阶段时，依赖的是阶段 ID，而不是复制共享阶段的节点内容。

### 节点定义

每一个公开展示的过程节点代表阶段内的一次有明确目标的创作行动，而不是每一次内部流式响应。节点至少包含：

```ts
interface ExampleStep {
  id: string;
  exampleId: string;
  phaseId: string;
  trackId: "book" | "comic" | "visual-novel" | "interactive-video";
  sequence: number;
  title: string;
  goal: string;
  status: "planned" | "in-progress" | "completed" | "needs-review";
  dependsOn: string[];
  userPrompt: string;
  promptContext?: string;
  model: ModelRun;
  humanDecision: string;
  outputRefs: OutputRef[];
  changedFacts?: string[];
  validation: ValidationResult[];
  createdAt: string;
  completedAt?: string;
}

interface ValidationResult {
  id: string;
  kind: "canon" | "timeline" | "character-state" | "stage-state" | "asset-reference" | "render" | "accessibility";
  status: "passed" | "failed" | "needs-review";
  summary: string;
  details?: string;
}
```

`userPrompt` 必须保存用户实际提交的提示词或经过公开展示授权的脱敏版本。系统内部若存在补充上下文、系统提示词或压缩摘要，应与用户提示词分字段保存，页面默认不把它们混成一段，避免用户误以为所有文字都来自用户。

### 模型运行信息

每条 Prompt 必须关联一次或多次模型运行。模型信息应足以复现“当时用了什么”，但不保存密钥：

```ts
interface ModelRun {
  provider: string;
  modelId: string;
  modelDisplayName?: string;
  modelVersion?: string;
  modality: "text" | "image" | "audio" | "video" | "mixed";
  parameters?: Record<string, string | number | boolean>;
  inputAssetRefs?: string[];
  outputAssetRefs?: string[];
  runStatus: "completed" | "failed" | "partial";
  generatedAt: string;
  durationMs?: number;
  usage?: {
    inputTokens?: number;
    outputTokens?: number;
    cost?: number;
    currency?: string;
  };
}
```

记录规则：

- `provider`、`modelId`、`modality`、`generatedAt` 是必填字段。
- 失败运行也保留，并展示失败原因或“未产出”，这样用户能看到真实迭代，而不是只看到成功结果。
- 模型参数只记录与作品质量或复现有关的字段，例如温度、尺寸、时长、宽高比和种子；绝不记录 API Key、OAuth token 或完整请求头。
- 费用、Token 数和时长若供应商不提供则显示“未提供”，不能推测或伪造。
- 一个节点如果比较了多个模型，应显示为同一 Prompt 下的候选运行，并记录最终选择理由。
- 图片、音频、视频生成 Prompt 与文本 Prompt 使用同一 `ExampleStep` 关联模型，但产物必须通过逻辑资产 ID 引用，不在故事源文件中写本地路径。

### 产物与版本

```ts
interface OutputRef {
  id: string;
  kind: "source" | "preview" | "asset" | "review" | "final";
  logicalAssetId?: string;
  path?: string;
  label: string;
  version: number;
  basedOn?: string[];
  isSelected: boolean;
}
```

页面要明确区分：AI 候选、人工选定版本、修订后版本和最终发布版本。只展示最后一张图或最后一段文字会丢失示例项目的学习价值。

## 四条媒介创作路径

四条路径不是从空白处各自开始。所有示例项目先经过一组共享设定阶段，形成统一的正典、角色、时间线和资产基线；之后才从“媒介规划”节点分叉。这样用户能理解：同一个故事核心如何被改写成小说、漫画、视觉小说和互动视频，而不是四个互不相干的模板演示。

### 共享设定阶段

共享阶段只做跨媒介都会复用的决定。它们属于 `example-world`，不是任何单一项目类型的私有内容。每个共享阶段都由多个 Prompt 节点推进：先探索，再收敛，再校验，最后冻结。

| 阶段 | 初始状态 | 阶段目标 | 多个 Prompt 推进 | 达成条件 | 产物 |
| --- | --- | --- | --- | --- | --- |
| S0 故事种子 | 只有“日本高中男女生穿越异世界”的方向和两章事件草案 | 确认裂缝、青梅竹马和共同穿越作为四媒介的核心故事承诺 | 1. 明确现代日本高中校园作为现实起点。2. 确认第一章“发现裂缝并约定调查”。3. 确认第二章“调查失败并一起被吸入”。4. 校验因果顺序和四媒介适配 | 四种媒介都基于同一组两章事件继续创作；不提前解释异世界完整设定 | 故事一句话、两章摘要、主题、媒介适配说明 |
| S1 主角设定 | 已知是一对日本高中青梅竹马，但姓名、具体年龄、班级、性格和外观未确认 | 固定两名主角档案、年龄、关系、动机、性格反差和第一章成长目标 | 1. 生成候选姓名、年龄和学校背景。2. 设计两人的互补性格与冲突。3. 生成关系变化曲线。4. 检查男生为何执着于裂缝、女生为何愿意相信并调查。5. 人工选择并冻结版本 | 两名主角能在四种媒介中保持同一身份；动机能解释关键选择；角色弧线可被拆到章节/页面/场景/片段 | `characters/male-student.md`、`characters/female-student.md` |
| S2 异世界规则边界 | 只有“异世界”概念，没有规则和限制；第一、二章不应解释异世界 | 只确定裂缝穿越的表现边界和需要后续回答的问题，不提前建立完整异世界秩序 | 1. 区分第一、二章可展示的裂缝现象和后续谜团。2. 确认设备无法检测的限制。3. 确认吸力触发穿越的表现。4. 列出异世界规则、回归条件和代价的待解问题。5. 检查四媒介是否能保留悬念 | 第一、二章不出现异世界完整解释；裂缝现象和穿越因果可被四媒介一致表现；后续世界观问题有清单 | `references/rules.md` 的第一版边界、`references/glossary.md` 的已知术语、待解问题清单 |

| S4 视觉与语气基线 | 有故事事实，但没有统一视觉与叙事气质 | 建立跨媒介共享的美术方向、地点氛围、角色外观和叙事语气 | 1. 生成视觉关键词和色彩方向。2. 生成男女主角外观描述。3. 生成异世界入口与首个地点描述。4. 生成资产逻辑 ID 草案。5. 校验是否可用于漫画、立绘、视频和小说插图 | 视觉描述足够具体但不绑定单一模型；资产以逻辑 ID 组织；语气能指导小说正文和对白 | 角色视觉描述、地点描述、色彩方案、资产逻辑 ID 草案 |
| S5 正典冻结 | S0-S4 已有候选设定，仍可能互相冲突 | 审核并冻结第一版不可改写事实，建立后续变更规则 | 1. 汇总 S0-S4 事实。2. 查找矛盾和重复定义。3. 生成修订建议。4. 人工确认最终事实。5. 输出正典变更规则 | 已确认事实只有一个来源；后续分支知道哪些内容可改、哪些必须走正典变更；检查项可复用 | `references/canon.md`、正典变更规则 |

共享阶段的每个节点仍然必须记录用户 Prompt、模型信息、候选输出、人工决策和验证结果。媒介分支引用共享节点时只保存引用关系，例如 `dependsOn: ["S1", "S2", "S3"]`，不要复制一份角色设定到各自轨道中造成事实漂移。

### 分支原则

- 共享阶段回答“这个故事是什么”。媒介阶段回答“这个故事在这种媒介里怎样成立”。
- 角色姓名、年龄、穿越事件、异世界规则和第一章关键因果只允许在共享阶段修改。
- 媒介阶段可以新增表现层设定，例如镜头、分镜、舞台状态、配音、节奏和交互选择，但不能无记录地改写共享正典。
- 如果某个媒介确实需要改变共享事实，必须新增“正典变更节点”，先回到共享阶段更新 `canon.md` 和受影响节点，再继续分支制作。
- 页面展示时应先显示共享阶段时间线，再让用户切换到各媒介分支；分支页顶部保留它依赖的共享设定摘要。

推荐的媒介分支节点如下：

### 漫画

漫画是本案例的第一条实际细化轨道。第一版先完整细化第一章和第二章，再扩展穿越后的异世界内容。漫画阶段必须优先确认“何时、何地、谁在场、人物处于什么状态”，然后再进入分镜和画面生成。

### 总览页

首屏应直接展示故事名称、男女主角、异世界核心冲突和四类媒介的完成状态。不要先放一篇产品宣传文案。总览页包含：

- 故事简介和正典摘要。
- 共享设定阶段进度，显示 S0-S5 已完成、待审核或需更新。
- 四个媒介进度入口，显示 `已完成`、`进行中` 或 `规划中`。
- “从头查看创作过程”和“从此案例开始创建”两个主要动作。
- 最终产物预览缩略图或明确的文本/流程预览。
- 最近一次模型运行与案例更新时间。

### 媒介详情页

详情页采用“最终结果 + 时间线”的布局：

- 顶部固定展示当前媒介的最终结果、完成定义和关键资产。
- 分支时间线前展示它依赖的共享设定摘要，以及可返回共享阶段的入口。
- 中部按顺序展示阶段时间线，阶段内再展开多个 Prompt 节点。
- 阶段展开后展示初始状态、阶段目标、达成条件、已完成 Prompt 数、阶段产物和完成证据。
- 节点展开后展示目标、用户 Prompt、模型卡、输入参考、候选输出、人工决策、校验结果和下一步。
- 提供“只看 Prompt”“只看模型”“只看产物”的筛选，不隐藏节点依赖关系。
- 支持从某个节点复制为新项目起点，复制时标记来源案例和来源节点。
- 支持在同一个页面切换四种媒介，并保留当前时间线位置。

### 节点详情

节点详情必须让用户分辨“输入、生成、选择、修改、验证”：

```text
目标
用户 Prompt
补充上下文（可选）
模型信息
候选输出与版本
人工选择 / 修改说明
校验结果
产生的文件或资产
下一节点
```

公开案例中的 Prompt 需要可复制，但复制按钮复制的是用户可执行版本，不包含内部密钥、内部系统提示或不可公开的上下文。

如果案例包含较大的二进制媒体，不应把所有媒体直接塞入首屏构建包。静态页面只加载 manifest、缩略图和文本节点，进入详情或预览后再加载对应资源；资源 URL、许可和生成状态都应在资产索引中明确。

用户派生项目应执行以下动作：

1. 复制选择范围内的源文件和允许复用的资产到新的 `<type>/<projectId>` OPFS 目录。
2. 写入来源信息，例如 `sourceExampleId`、`sourceStepId` 和复制时间。
3. 将案例只读过程记录转换为用户项目的初始上下文副本，后续用户修改不回写案例。
4. 依照已有 source ZIP、预览、导出和类型识别流程处理派生项目。

### 内容许可与公开级别

每个案例节点需要有 `visibility`：`public`、`redacted` 或 `internal`。只有 `public` 和经过脱敏的 `redacted` 内容进入公开页面。模型运行记录中的密钥、用户隐私、供应商内部标识和临时 URL 必须在发布前移除。

## 分阶段交付

### 阶段 1：正典和数据合同

- 确认故事标题、核心冲突、男女主角姓名、年龄、性格、第一章事件和第二章穿越事件。
- 建立 S0-S5 共享设定阶段、案例 manifest、四条媒介轨道和节点/模型/产物类型。
- 规定 Prompt 脱敏、资产逻辑 ID、模型字段和公开级别。
- 用一个完整文本节点和一个失败模型节点验证数据能表达真实迭代。

验收：数据合同可以同时表达共享设定阶段、四种媒介分支、候选版本、失败运行、人工选择和最终产物，且不包含密钥。

### 阶段 2：最小完整案例内容

- 先完成 S0-S5 共享设定阶段和小说轨道，作为四类案例的事实基线。
- 为漫画、视觉小说和互动视频各完成最小可验证成品路径。
- 漫画轨道先完成 C0-C5 六个阶段，并为第一章和第二章分别保留完整的阶段过程；其他轨道各自至少提供 6 个过程节点，不能只提供最终结果。
- 每个轨道至少记录 1 个文本 Prompt、1 个媒体或资产 Prompt、1 次人工修订和 1 次校验。

验收：用户从共享设定第一个节点开始浏览，能连续理解共享事实如何建立，以及每条媒介分支为什么基于这些事实继续制作。

### 阶段 3：只读示例页面

- 实现 `/examples` 总览页和四个媒介详情页。
- 添加阶段时间线、阶段展开、节点展开、Prompt 复制、模型信息展示和产物版本切换。
- 适配桌面和移动端，长 Prompt 和模型参数必须换行，不依赖横向滚动。
- 对未生成媒体显示明确状态和下一步，不显示破损图片或空白播放器。

验收：不创建用户项目也能完整浏览案例；刷新页面后静态案例仍可访问；四类媒介入口、共享阶段、分支阶段、节点和最终结果均可到达。

### 阶段 4：从案例派生项目

- 支持从总览页复制完整案例。
- 支持从任意已完成节点复制对应轨道。
- 支持只复制正典、角色和 Prompt 集合。
- 复用已有项目创建、OPFS、source ZIP、预览和导出链路。

验收：派生项目拥有新的项目 ID；案例只读数据不被修改；用户可以在真实项目文件中继续编辑、预览、备份和导出。

### 阶段 5：质量和公开发布检查

- 检查四种媒介的正典、角色状态和时间线是否一致。
- 检查所有资产引用是否为逻辑 ID，禁止在故事文件中硬编码文件路径。
- 检查模型信息、Prompt 和产物版本是否一一对应。
- 检查公开内容是否移除了密钥、个人信息、临时 URL 和未授权资源。
- 检查移动端布局、键盘操作、复制反馈、加载状态和错误状态。

## 验收标准

### 功能

- 用户可以从案例总览进入小说、漫画、视觉小说和互动视频四条创作路径。
- 用户可以先查看共享设定阶段，再进入任一媒介分支。
- 每条路径都能按顺序查看从概念到当前目标的阶段，且每个阶段能展开查看多个 Prompt 节点。
- 每个阶段都展示初始状态、阶段目标、达成条件和完成证据。
- 每个节点都能看到用户 Prompt、对应模型信息、输出版本、人工决策和验证结果。
- 用户能区分模型候选输出、人工选定版本、修订版本和最终版本。
- 用户能从完整案例或指定节点创建新项目，且不会修改只读案例。
- 视觉小说节点与现有浏览器预览和 OpenWebGal 导出约定相容。
- 缺少图片、音频或视频时，页面显示明确的资产状态和影响，不伪造完成度。

### 内容

- 四种媒介共享同一套男女高中生穿越异世界的正典。
- 共享设定阶段至少覆盖故事种子、主角设定、裂缝/穿越规则边界、两章时间线、视觉语气基线和正典冻结。
- 每条媒介路径至少有规划、生成、修订和验证阶段，每个阶段至少包含 2 条 Prompt 节点，不能用单次生成冒充阶段完成。
- 案例可解释至少一次失败或未采用的模型运行，展示真实决策过程。
- 公开 Prompt 可复制、可理解，并与其模型和产物绑定。
- 最终展示符合各媒介的完成定义，而不是四种媒介都只展示 Markdown。

### 工程与安全

- 案例详情页优先静态生成，浏览器 API 只在派生项目或用户交互时调用。
- 首屏不加载不必要的大型二进制资源。
- 案例数据不包含 API Key、OAuth token、内部请求头或不可公开的用户内容。
- 派生项目遵守现有 `<type>/<projectId>` OPFS 目录和 source ZIP 约定。
- 通过 lint、类型检查、相关单元测试、构建和 `git diff --check`。
- 至少完成桌面和移动端浏览器验证，并验证时间线展开、Prompt 复制、模型信息显示和派生项目入口。

## 风险与未决问题

### 风险

- 四条路径若各自改写故事，会导致角色状态和时间线漂移；必须把共享正典设为高优先级来源。
- 模型名称、版本和计费字段在不同供应商中不一致；展示层要允许缺省值，不能把推测值当事实。
- 大型图片、音频和视频会拖慢静态页面；需要缩略图、延迟加载和明确的资产清单。
- 公开 Prompt 可能包含个人信息或供应商敏感信息；发布流程必须有脱敏和可见性校验。
- 案例过程记录过多会让用户难以阅读；默认按节点摘要展示，详细信息按需展开，同时保留完整顺序。

### 实现前必须确认

- 四类媒介的案例是否共用一个项目 ID，还是使用一个案例 ID 加四个轨道 ID。
- 最终案例内容由仓库静态发布，还是未来允许从用户项目发布为公开案例。
- 是否展示真实费用和 Token 数；若展示，需要确定各模型供应商的统一口径。
- 漫画、互动视频的首批媒体资产是否已获得公开展示和再分发许可。
- 视觉小说和互动视频的“可运行最终结果”第一版支持到什么程度，哪些资产允许保留为待生成计划。
- 派生项目是否复制所有过程记录，还是只复制选定节点生成的源文件、资产和 Prompt 集合。
